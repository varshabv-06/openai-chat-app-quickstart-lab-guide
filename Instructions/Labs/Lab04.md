# Lab 04: Monitor the Chat Application using Log Analytics Workspace

A Log Analytics Workspace in Azure collects and stores logs generated by Azure resources such as Container Apps. It allows users to run queries using Kusto Query Language (KQL) to monitor application behavior, analyse performance, and troubleshoot issues.

### Estimated Duration: 30 minutes

## Overview

In this lab, you will access the Log Analytics Workspace connected to your deployed chat application and analyse logs generated during runtime.

## Objectives

In this lab, you will perform the following:

- Task 1: Navigate to the Log Analytics Workspace
- Task 2: Analyse Application Logs using KQL Queries


### Task 1 - Navigate to the Log Analytics Workspace

In this task you will open the Log Analytics Workspace that is connected 
to your Container App and access the Logs section to run KQL queries.

1. Generate some log data first by opening your chat application in 
   the browser and sending 3 to 4 messages:

    https://`<your-container-app-url>`

    Wait 2 to 3 minutes after sending messages before proceeding. 
   This gives Azure time to ingest the logs into the workspace.

   > **Note:** Log data is not instant. Azure typically takes 2 to 5 
   minutes to ingest logs after activity occurs in the application.

1. Navigate to the Azure Portal:

    https://portal.azure.com

1. In the Search bar type **Log Analytics workspaces (1)** and select 
   **Log Analytics workspaces (2)**.

    ![](../media/l4-t1-s3.png)

1. From the list of workspaces click on 
   `<your-unique-name>-loganalytics`.

    ![](../media/l4-t1-s4.png)

1. On the left menu click **Logs** under the General section.

    ![](../media/l4-t1-s5.png)

1. If a **Queries** popup window appears, click the **X** to close it 
   and proceed to the query editor.

1. To verify your log tables are available click the **Tables** icon 
   **(1)** on the left sidebar of the query editor. Expand 
   **LogManagement** → **Custom Logs (2)** and you will see 
   **ContainerAppConsoleLogs_CL (3)** and 
   **ContainerAppSystemLogs_CL** listed.

    ![](../media/l4-t1-s9.png)

     These two tables contain all logs from your Container 
   App. `ContainerAppConsoleLogs_CL` contains application output logs 
   and `ContainerAppSystemLogs_CL` contains infrastructure-level 
   system events.

    ![](../media/l4-t1-s7.0.png)

1. On the top right of the query editor, click the mode dropdown and 
   select **KQL mode**. This ensures you are writing Kusto Query 
   Language queries.

    ![](../media/l4-t1-s7.png)

1. Change the **Time range(1)** at the top to **Last 7 days(2)** by clicking 
   on the time picker dropdown. This ensures you can see all logs 
   generated during the lab.

    ![](../media/l4-t1-s8.png)


   


### Task 2 - Analyse Application Logs using KQL Queries

In this task you will run KQL queries to view different types of log 
data. Each query reveals different information about how the 
application is running. The results will show columns including 
`TimeGenerated`, `ContainerImage_s`, `Category`, `Stream_s` and 
`Log_s`.

1. **View Console Logs**

   Console logs show everything the application outputs during 
   execution — startup messages, request handling, errors, and 
   responses. Clear the editor, paste the following query and 
   click **Run**:
    ```kusto
    ContainerAppConsoleLogs_CL
    | where TimeGenerated > ago(7d)
    | project TimeGenerated, ContainerName_s, Log_s
    | order by TimeGenerated desc
    | take 50
    ```

    ![](../media/l4-t2-s1.png)

1. **Explore All Available Columns**

   To see the full set of columns available in the logs table click 
   on any row in the results to expand it. You can also run this 
   query to see all columns including container image, category, 
   and stream information:
    ```kusto
    ContainerAppConsoleLogs_CL
    | where TimeGenerated > ago(7d)
    | take 10
    ```

    ![](../media/l4-t2-s2.png)

1. **Count Log Activity Over Time**

   This query groups log entries by hour and shows you when the 
   application was most active. Clear the editor, paste the 
   following and click **Run**:

    ```kusto
    ContainerAppConsoleLogs_CL
    | where TimeGenerated > ago(7d)
    | summarize RequestCount = count() by bin(TimeGenerated, 1h)
    | order by TimeGenerated desc
    ```

   ![](../media/l4-t2-s3.png)

>**Summarization:** Monitor using Log Analytics Workspace (30 min)
Users send messages in the chat app to generate logs, navigate to the Log Analytics Workspace in the portal, switch to KQL mode, and run three queries — console logs, full column exploration, and log activity count over time — to understand how the application is running in production.
